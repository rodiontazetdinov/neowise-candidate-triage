# Тестовое Neowise. AI-помощник для входящих заявок

Ориентир — 45–60 минут. Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

## Запуск и тесты

Нужен Node.js 20 или новее. Зависимостей и ключей нет, `npm install` не требуется.

```sh
node server.mjs        # или npm start; затем откройте http://127.0.0.1:3000
npm test               # то же самое: node --test
```

Порт можно задать через переменную `PORT`. Проверить сбой вручную: введите на странице `Где доставка? [bad-topic]` (или `[timeout]`, `[error]`, `[bad-json]`, `[empty-draft]`). Очередь ручного разбора: http://127.0.0.1:3000/api/review-queue.

## Что сделано

**API (`server.mjs`, `lib/triage.mjs`)**

- Ввод: битый JSON, не объект, нет `text`, не строка, пустая или пробельная строка, слишком длинное тело дают HTTP 400 и `{"status":"invalid_input"}`. Текст обрезается по краям.
- Ответ AI проверяется по схеме в `validateModelOutput`: валидный JSON-объект, `topic` из `delivery`, `pricing`, `other`, `draft` непустой после `trim`.
- Ожидание модели ограничено 300 мс общим бюджетом: `AbortController` передаётся в имитатор, а `Promise.race` обрывает вызов, даже если модель не слушает `signal`.
- При ошибке модели или неподходящем ответе делается один повтор в пределах того же бюджета. Таймаут не повторяется, бюджет уже исчерпан.
- Если результата нет, ответ HTTP 200 `{"status":"manual_review","topic":null,"draft":null}` строго по контракту. Причина (`timeout`, `model_error`, `invalid_json`, `invalid_shape`, `unknown_topic`, `empty_draft`) уходит в заголовок `X-Triage-Reason`, в лог и в очередь ручного разбора `GET /api/review-queue` (в памяти процесса, последние 100 заявок).
- Имитатор `mock-ai.mjs` не менялся. Для тестов модель подставляется через `createApp({ classify })`.

**Страница (`index.html`, `public/app.mjs`)**

- Пустой ввод не отправляется, показывается подсказка.
- Во время запроса видно «Разбираем заявку…», старый результат сразу убирается.
- Тема и черновик показываются только для валидного `ready`. При `manual_review`, ошибке сети, 500, неожиданном ответе или клиентском таймауте (5 с) показывается сообщение о ручном разборе, тема и черновик стираются.
- Гонка ответов: каждый запрос получает растущий `requestId`, предыдущий отменяется через `AbortController`, устаревший ответ отбрасывается.
- Логика вынесена в `public/app.mjs` без зависимости от DOM, поэтому проверяется в `node:test`.

**Тесты (`test/`, 19 штук, `node:test`)**

- `api.test.mjs`: настоящий сервер с настоящим имитатором: успех, пустой и битый ввод, все пять меток сбоя дают `manual_review` с нужной причиной быстрее 600 мс, очередь ручного разбора.
- `triage.test.mjs`: схема ответа, один повтор с успехом, два сбоя подряд, таймаут модели, игнорирующей `signal`.
- `frontend.test.mjs`: пустой ввод, черновик стирается при сбое, гонка (первый ответ через 500 мс, второй сразу, на экране второй), клиентский таймаут.

## Польза для менеджера

Менеджер никогда не видит пустой или мусорный черновик и не отправит клиенту ответ на чужую заявку: устаревшие результаты отбрасываются. При сбое он за доли секунды получает понятное сообщение вместо зависшей страницы, а заявка с причиной попадает в очередь ручного разбора и не теряется. Измерить: доля заявок в `manual_review` по причинам, время до первого ответа клиенту и число ответов, отправленных с исправлениями черновика.

## Исходное задание

### Что изменить

1. Доработайте `POST /api/triage`. Принимайте JSON с полем `text`, содержащим непустую строку. При пустом, отсутствующем, нестроковом вводе или битом JSON верните HTTP 400 и `{"status":"invalid_input"}`.
2. При корректном ответе модели верните HTTP 200 и `{"status":"ready","topic":"…","draft":"…"}`. Допустимые темы — `delivery`, `pricing`, `other`. Черновик должен быть непустой строкой. При таймауте, ошибке модели или неподходящем ответе верните HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. Ограничьте ожидание модели 300 мс. Оставьте поведение выданного имитатора прежним.
3. Покажите на странице тему и черновик при успехе. Для `manual_review` покажите понятное сообщение менеджеру и очистите предыдущий черновик. Добавьте хотя бы один исполнимый тест для поведения при сбое и инструкцию его запуска.

Для локальной проверки имитатор принимает любой обычный текст. Метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` включают отдельные сценарии сбоя.
